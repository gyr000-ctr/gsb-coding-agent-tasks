搜索框下面那个补全要自己实现一遍：一份压缩前缀树，支持按前缀取 top-k、按编辑距离模糊找近的、删除
之后还要能把树收回去（不能越用越胖）。环境里没有现成的，自己写一份。

入口就 createIndex，出来的对象上有 insert / remove / has / weight / prefix / fuzzy / top / stats，
README 的《口径》和《API》两节是标准答案：词和权重怎么校验、排序怎么定（权重降序再按词条码元升序，
fuzzy 前面还多一层距离升序）、压缩树里哪些位置才算一个节点、删除以后怎么合并回收、前缀正好落在边标签
半截上算什么、编辑距离按什么算、模糊匹配的遍历顺序和访问预算怎么数、哪些子树不许进、各种坏参数报哪个码，
都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差
lib/typemap.js，别的文件不动（用例是标准，别改用例去迁就实现），也别引第三方包。

容易写歪的地方：整棵树的比较和长度都按 UTF-16 码元算，emoji 是一个词里占了两个码元的普通字符，
别按码点切；stats().nodes 只数根、词尾、岔路口，中间直溜溜的节点没有实体，空表是 terms 0 / nodes 1；
删除要把「没有儿子」的词尾节点摘掉、把「只有一个儿子且自己不是词尾」的节点并回父边，一路递归上去，
这样删了再插回来 stats 才能跟原来一模一样，别只是把词尾标记抹掉；前缀查询走到边标签中间时整棵子树
都命中，累加出来的词必须是完整的词（把边的前半截也算进去，别只拼剩下那半截）；fuzzy 的预算是「从根
开始、儿子按边标签码元升序深度优先、进一个节点算一次访问（根也算）」，DP 行最小值已经超过
maxDistance 的子树不许再进，超预算立刻抛 ERR_BUDGET_EXCEEDED，details.visits 要给出来；编辑距离是
Levenshtein（插删换各 1），不要写成 LCS 或者带换位的 Damerau；insert 对已经有的词是改权重返回 false，
不是报错也不是重复计数；权重可以是 0 和负数，排序时按数值比；limit 会给 0，那时候要返回空数组；
prefix 和 fuzzy 的 term / prefix 参数里空串，prefix('') 等于 top，但 fuzzy('') 是非法的；
代码元顺序排序要用 < 比较或者 sort() 默认那一套（别按 localCompare 或数值化）。

大小写、createIndex 的两种写法与重复词、两千个词的规模、同样的操作得到同样的结果），npm run demo 的
输出跟 README 最后贴的那段一行行对上。
