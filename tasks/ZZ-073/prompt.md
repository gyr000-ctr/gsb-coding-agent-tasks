手上要个跑在定长区间上的分配器：一块 size 字节的地，自己切块分出去、释放回来还得把相邻的空闲块合并，
免得越用越碎。环境里没有现成的，自己写一份。

入口就 createHeap({ size, strategy })，出来的对象上要有 alloc / free / capacity / read / write / dump / stats。
README 的《口径》和《API》两节是标准答案：每块前面那 8 字节头怎么算进占用、申请 n 字节要占多大的块、
指针为什么是块起始加 8、first 和 best 各自挑哪块、切完剩下的剩多少才值得切、释放以后往哪个方向合并、
指针什么时候算非法、读写越界报什么、dump 和 stats 里各字段什么含义、错误码和 details 各带什么，
都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，
就差 lib/heapfit.js，别的文件不动（用例是标准，别改用例去迁就实现），也别引第三方包 ——
更不是让你随便把块列表按 offset 排一遍就完事，头、对齐、最小剩余和合并这几条都会算错。

容易写歪的地方：申请 n 字节占的是 ceil((n + 8) / 8) * 8，头也算在里面，别只算 n 或者漏掉对齐；
返回的指针是块的起始再加 8，所以最小是 8、一定是 8 的倍数，0 永远不是合法指针；切完剩下的不到 16 字节
就别切了，整块都给出去（多出来的算在占用块的 size 里，capacity 还是当初要的那个数），剩下正好 16
是要切的；best 是「装得下里面最小的那块」，并列取 offset 小的，first 是「第一块装得下的」，
别把两个写反；free 要跟左邻右舍的空闲块都合，合完还得接着往下合，空闲块之间永远不许挨着；
重复释放、野指针、0、没对齐、乱传类型，统一 ERR_BAD_POINTER，别有的报 ERR_BAD_ARGUMENT 有的静悄悄返回；
指针先查再查长度，p 不活着的时候 length 非法也轮不到报；写进去的比申请的多要报 ERR_OUT_OF_BOUNDS
并且 details 里给 requested 和 capacity，短的只盖前面那几个字节、后面别动；read 出来的得是拷贝，
改它不能影响堆里那份；没写过的地方是 0；dump 给的也是拷贝，改了不能影响内部；
stats 的 used 是占用块字节和（含头）、free 是空闲字节和，两个加起来永远等于 size，空闲块全分出去了
largestFree 才是 0；createHeap 的 strategy 不写默认 best，但写了 'FIRST' 这种大小写不对的算非法；
size 不是 8 的倍数也得正常跑（100 的堆上申请 80 会整块给走）；几千次分配释放之后账还要对得上，
别写成一次操作就要重排全表那种。
