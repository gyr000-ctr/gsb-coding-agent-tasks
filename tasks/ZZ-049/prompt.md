板子上那套周期任务一直靠拍脑袋排优先级，上线以后偶尔冒出来一个误期，谁也说不清是排法不对
还是本来就挤不下。想在这仓库里把最早截止期优先这块写出来：先判能不能排得开，再把时间线
一格一格重演出来，事后能拿它跟现场对。

入口就 analyze、simulate、hyperperiod 三个，README 的《口径》和《API》
两节把任务怎么定义、利用率怎么算、可调度的判据、超周期怎么取、每格挑谁跑、并列怎么破、
误期怎么记、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/realtime.js，别的文件别动，
也别引第三方包。

几个我特别在意的地方。利用率必须是精确分数，一路用 BigInt 通分再加，不许拿浮点凑：
1/2 + 1/3 + 1/6 用浮点算出来是 0.9999999999999999，这边必须是不多不少 1，
判定的结论也跟着这个分数走，别让人因为浮点误差看到 "差一点点" 这种结论。

重演那一段要复现得一模一样：每格开始先放新作业，然后在已释放且没跑完的里面挑绝对截止期
最小的；截止期一样就比任务 id 的字典序，这也是钉死的。后释放但更紧的作业要能抢占正在跑的。
跑完一格要检查误期：到点了还没跑完就记一笔并且丢掉，不许补跑。区间要合并——连着好几格
跑同一个作业得是一段，空着的相邻格子也要并成一段，不然输出没法看。

跑法两条：npm test 全绿（10 条，里面有精确分数与浮点陷阱、可调度与不可调度的判定、
任务表的校验、超周期、抢占时间线、恰好跑满不出空闲、并列截止期按 id、
误期与丢弃、until 的默认值与上限、空闲区间合并），npm run demo 的输出跟 README
最后贴的那段一行行对上。
