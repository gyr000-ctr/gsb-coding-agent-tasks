备份那边要换个存法：一份数据切成一堆等长的块，另外算几个校验块放着，哪台机器上的块坏了或者说硬盘读不出来了，
手里剩下的块够多就能把那几块推回来。别引库，环境里没有，自己从 GF(256) 开始写。

入口五个：gfMul、gfDiv、gfPow、encode、decode，README 的《口径》和《API》两节是标准答案：本原多项式是哪个、
生成元是谁、系数矩阵怎么摆（第 j 个校验块乘 α 的 (j+1)*i 次幂）、k / m 怎么传、返回的块长什么样、
哪些位置算「丢了」、缺多少块还能补、方程怎么挑、补不回来报什么、错误码和 details 各带什么，都写死了，
照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/rscodec.js，
别的文件不动（用例是标准，别改用例去迁就实现），也别引第三方包 —— 更不是让你手搓一张固定的生成矩阵糊过去，
用例里既有写死的校验块向量，也会把丢块的所有组合跑一遍。

容易写歪的地方：本原多项式是 0x11d 不是 0x11b，生成元是 2，所以 gfPow(2, 8) 得是 0x1d、gfPow(2, 255) 是 1；
gfPow 的指数要按 255 取模，gfPow(x, 0) 一律是 1（0 的 0 次方也是 1），而 gfMul 只要有一边是 0 就是 0，
别把这两件事混了；gfDiv 除以 0 要报 ERR_BAD_ARGUMENT，被除数是 0 返回 0。encode 返回的前 k 个是数据块的拷贝，
改返回的数组不能影响传进来的那几个，长度 0 的块也得能跑。decode 的 shards 长度必须正好是 data + parity，
丢的位置写 null、别的位置必须是 Uint8Array 且长度一致，缺的块数把数据块和校验块一起算，超了 parity 报
ERR_TOO_MANY_ERASURES。求解的时候未知量只是缺掉的数据块，缺的校验块不用管；用还在的数据块把等式右边算出来，
再在 GF(256) 上做高斯消元（要选主元、要归一化），方程按位置从前往后取前 u 条还在的校验块，这样同一组输入
解出来是唯一的；k 个数据块全丢了也得能补（只要 m >= k）。数据块都在的时候别去验算校验块，直接拷回来就行 ——
这里不是校验和，值被改坏了是查不出来的。返回的数据块按原下标排好，没丢的那几个也返回拷贝。

details），npm run demo 的输出跟 README 最后贴的那段一行行对上。
