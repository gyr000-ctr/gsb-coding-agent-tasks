库存和配置中心那边一直是"读的时候加锁、写的时候加锁"，热点行一压就全串行，而且两个人同时改同一行，后写的把先写的悄悄盖掉，谁都发现不了。想在这仓库里换成带版本的事务存储。

入口一个 createStore，README 的《口径》和《API》两节把版本号怎么走、事务怎么开怎么提交怎么回滚、快照隔离到底看哪一刻、写写冲突怎么判、scan 的区间口径、旧版本什么时候能回收、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/store.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。事务只能看到它开始那一刻已经提交的东西，开始之后别人提交的改动它就是看不见，别写成读最新。冲突只认写集：读过但没写的 key 被别人改了不算冲突，真撞上了就得整个事务作废，不能只把冲突那一个 key 回滚掉。scan 是半开区间，自己没提交的写和删都得反映在结果里。

回收这块最容易出事：每个 key 的最新版本永远得留着，另外还活着的事务快照在某个 key 上看得见的那一版也得留着，不然老事务读着读着就读空了。存进去的、读出来的都必须是拷贝，外面改它不能影响库里存的那份。

跑法两条：npm test 全绿（14 条，里面有快照隔离、写写冲突只认写集、半开区间与排序、活跃快照钉住旧版本、墓碑不回收、深拷贝、各条参数校验），npm run demo 的输出跟 README 最后贴的那段一行行对上。
