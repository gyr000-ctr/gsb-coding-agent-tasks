我们的文档协作现在是"谁要改就整篇传一份最新的"，两个人同时改就丢改动。想在这仓库里改成按字符发增量的副本，谁收到什么顺序都不影响最后的结果。

入口一个 createReplica，README 的《口径》和《API》两节把索引按什么单位算、字符身份怎么拼、插入挂在哪个锚点上、同一锚点下的兄弟怎么排序、本地插入和删除产出的 op 长什么样、收到别人的 op 之后哪些情况压缓冲哪些算重复、返回值的含义、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/replica.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。并发插入的定序必须两边算得一样，不然两个人看着不同的文本，这个最要命。删除是墓碑不是真删，别人锚在被删字符上的插入还得留在原位。索引是 JS 字符串下标也就是 UTF-16 码元，不是码点。

收到的 op 不能直接套用：seq 接不上要压着等前一条，锚点字符或者要删的字符还没到也得压着，等到了再自动落位。同一个 op 投两次只能生效一次。我要的是投递顺序随便换，最后还是同一份文本。

跑法两条：npm test 全绿（13 条，里面有并发同位置插入定序、一边删一边插、同副本乱序补齐、跨副本锚点等待、多个副本任意投递顺序都收敛、重复投递、参数与 op 校验），npm run demo 的输出跟 README 最后贴的那段一行行对上。
