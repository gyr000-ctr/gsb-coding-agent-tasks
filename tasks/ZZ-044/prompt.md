入口一个 createIgnore，README 的《口径》和《API》两节把规则怎么读、通配怎么走、目录剪枝怎么算、
路径怎么写、大小写怎么处理、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/globignore.js，别的文件别动，
也别引第三方包。

锚定和浮动是两码事：带斜杠的规则从根开始整条路径都要对上，不带的
才哪一层都算，有人把 dist 写成了 /dist 就只排掉根上那一个。跨目录的那两个星号更坑，
夹在中间的时候它可以一层都不吃，所以 docs/**/tmp 得能匹配 docs/tmp；可写在结尾的时候
它至少要吃掉一层，cache/** 管的是 cache 里面的东西，不是 cache 这个目录自己。

最要命的是目录剪枝：只要有一层祖先目录被判成忽略，下面写的取反规则就不能当没看见继续翻案——
这条跟人直觉是反的，但这才是 .gitignore 的规矩，我要的就是这个。反过来，父目录自己要是被
后面的取反规则救回来了，里面的文件就还能各自判各自的。剪枝的时候报出来的得是最外面那一层，
不然让人瞎猜是哪层的问题。

跑法两条：npm test 全绿（14 条，里面有注释与空行、行尾空格与转义、锚定与浮动、* 和 ? 不跨段、
** 的零层与至少一层、字符类与取反类、最后一条命中、目录剪枝与 blockedBy、父目录被救回、
大小写开关、partition 保序、各种非法规则的错误码），npm run demo 的输出跟 README 最后贴的
那段一行行对上。
