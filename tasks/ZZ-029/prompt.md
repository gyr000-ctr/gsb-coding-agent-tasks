我们要给客户推事件通知，之前的实现老是重复推、失败也不重试，客户回 410 还照推不误，想在这仓库里重写一个出站 webhook 投递器。

入口一个 createDispatcher，README 的《口径》和《API》两节把配置、订阅与退订、事件匹配、投递对象和三个请求头、签名怎么算、body 怎么规范化、report 的判定与退避、410 停投、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/dispatcher.js，别的文件别动，也别引第三方包。

幂等要做到事件级：同一个 event.id 对同一个订阅者只能有一条投递，重复派发时把已有的 id 放进 duplicates 返回，不能再建一条。签名和幂等键都得稳定——body 用键排序的紧凑 JSON 编出来，签名素材是"签发秒数 + 点 + body"，取 HMAC 前 16 位十六进制。

report 的顺序要清楚：先认投递在不在、参数合不合法；2xx 算成功；410 是对方不要了，这条进死信并且把这个订阅者停掉；其它状态先看次数用完没有，没完就退避重排（Retry-After 优先但仍受 maxDelayMs 截断）。due 只给到期的，按到期时间和 id 排序。"现在几点"只能从 clock 拿。

跑法两条：npm test 全绿（11 条，里面有事件匹配、重复派发去重、退订、签名与幂等键、2xx/500/410 三条路径、退避与截断、参数错误），npm run demo 的输出跟 README 最后贴的那段一行行对上。
