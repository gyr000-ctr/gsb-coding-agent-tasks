榜单接口现在是 limit + offset 翻页，线上数据一直在动：翻到第二页的时候前面插进来一条，
用户就会看到重复的条目；有人的分正好被删掉，下一页还会整个错位。想在这仓库里把分页换成
游标式的，顺便把"多键排序 + 翻页稳定"这块补出来。

入口一个 createPager，README 的《口径》和《API》两节把配置校验、值的先后顺序、游标里存什么、
怎么签名和验签、过期怎么算、page 的判断顺序、每种错误报哪个码都写死了，照着来。目录里
lib/codec.js、lib/errors.js、test 下三组用例、scripts/demo.mjs 都已经写好，就差 lib/pager.js，
别的文件别动，也别引第三方包。
排序是唯一确定的：多键、每个键各自 asc/desc，值按 null < 数字 < 字符串
< 布尔 的固定先后比，比完一律再用 id 升序兜底，别的类型直接当脏数据拒掉。游标里不能只存 id：
得存最后一个排序键的值和方向，翻页时按"键值 + id"找第一行严格更大的，**不能去反查那一行还在不在**，
否则那行删了整页就废了。

游标是要签名的，改一个字符、换一把 key、拿另一个排序规格的分页器来解，都得报 ERR_BAD_CURSOR；
过期按注入的 clock 算，超过 ttlMs 报 ERR_EXPIRED。"现在几点"只能从 clock 拿，别在代码里
偷偷 Date.now()，不然过期边界测不了。

limit 有默认值和上限，越界报 ERR_BAD_LIMIT；filter 在排序之前生效，total 报过滤之后的行数，
nextCursor 只在确实还有下一页时给，最后一页必须是 null。

跑法两条：npm test 全绿（17 条，里面有类型先后、多键排序、游标篡改/过期/规格不匹配，
以及翻页期间插入到游标之前、相同键值但 id 更小、删掉游标那一行这三种稳定性场景），
npm run demo 的输出跟 README 最后贴的那段一行行对上。
