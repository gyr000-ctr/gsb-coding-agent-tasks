下单、支付这类接口最怕客户端超时重试，一秒里同一笔订单被提交三次就重复扣款了，想在这仓库里加一层幂等执行器。

入口一个 createExecutor，README 的《口径》和《API》两节把配置、run 的三种结果、指纹冲突怎么处理、过期怎么算、异常怎么算、has/forget/prune 的行为、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/executor.js，别的文件别动，也别引第三方包。

重复请求不能再跑业务逻辑：key 一样、指纹一样、还没过期就直接回放第一次的结果，handler 一次都不能被调用；key 一样但指纹变了要报 ERR_FINGERPRINT_MISMATCH，这通常说明客户端复用了幂等键却改了请求体。handler 抛异常的时候不要记账，让下次重试还能正常执行。

记录有过期时间，now 减首次执行时间到 ttlMs 就算过期，到点之后再来的同一个 key 会重新执行并覆盖记录；存下来和回放出去的结果都必须是深拷贝，外面改它不能影响后面。"现在几点"只能从 clock 拿。

跑法两条：npm test 全绿（10 条，里面有执行与回放、handler 调用次数、指纹冲突、异常不记账、过期重跑、prune 与统计），npm run demo 的输出跟 README 最后贴的那段一行行对上。
