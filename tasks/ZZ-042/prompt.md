灰度开关现在散在代码里，想按用户放量只能靠"取模用户 id"，换个权重就把人洗一遍牌，开关之间也没法互相依赖。想在这仓库里写个统一的开关求值引擎。

入口一个 createFlagEngine，README 的《口径》和《API》两节把开关怎么定义、规则怎么匹配、灰度怎么分桶、依赖怎么算、版本怎么走、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/flagr.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。分桶哈希要一字不差地照做（FNV-1a 32 位，按 UTF-8 字节走，键是"开关名:用户"），而且分桶只看开关名和用户，不看权重——所以把权重从一半提到九成，已经在里面的人不会掉出去，只有边上的人被挪进来。

求值顺序是依赖、规则、灰度、兜底，四步不能乱：依赖拿的是同一个 context，只要有一个对不上就直接落到 offVariation 并且理由标成 prerequisite，别去跑规则。规则按声明顺序，第一条命中就结束。条件里"缺这个属性"和"属性值是 null"是两回事：eq 拿 null 比只对显式的 null 成立，exists 只看这个键在不在；字符串和数值那几类算子还要求两边类型对得上。

定义的时候该拦的都要拦：灰度权重必须是 0 到 1000 的整数且加起来正好一千，引用的开关必须已经定义、引用的 variation 必须存在，更新的时候还要能查出依赖成环（包括指向自己）；还被别人依赖着的开关不让删。统计只数顶层那一次求值，依赖递归出来的不算。

跑法两条：npm test 全绿（15 条，里面有同一个人分桶稳定、权重变化不洗牌、权重校验、规则优先与顺序、兜底、依赖不满足、evaluateAll 与 list 排序、各算子与 null / 缺属性、match 的 all / any 与空条件、定义校验、环检测与删除保护、统计口径），npm run demo 的输出跟 README 最后贴的那段一行行对上。
