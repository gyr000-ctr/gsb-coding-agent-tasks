我们对外那个 API 网关最近被合作方折腾得够呛。他们超时了就自己重发，同一笔请求一秒钟能打到
我们八次；反过来我们这边也没做好，有人改了个 body 拿着上周的签名照样能过。我想在这条路上加
一层请求签名校验，签名算法和时间窗都跟合作方谈好了，仓库 ./signgate 就是给这块留的位置。

骨架已经在里面了：规范串和签名算法（src/canonical.js）、密钥表、共享存储（线上是 Redis，
这里把我们会用到的那几条命令一条条模拟出来了，都标了是不是原子的）、HTTP 那层、计数器、
错误类型、配置解析、演示入口都在，用例也在，唯独 src/verifier.js 和 src/nonce-store.js
是空的，现在只会抛 not implemented。README 把五个头的名字、规范串怎么拼、每一步失败报什么
code、计数器叫什么名字、nonce 的 key 怎么拼都写清楚了，照着来；已有文件的接口、configs、
test 里的用例都别改，package.json 也保持现在这样。别装包，node 20 的标准库够用。

防重放是重点。同一个 nonce 在 TTL 里只能用一次，这个判断必须是原子的——线上有好几个网关
实例，nonce 都放在共享存储里，先查一下再写是错的，五十个请求一起打进来会一起读到"没有"，
然后一起放过去。还有顺序上的坑：签名没验过之前不许去认领 nonce。合作方那批请求是同一秒里
批量发的，要是乱签名的请求也能把 nonce 烧掉，他们真正的请求就会全被我们拦成重放，这个我
踩过。

共享存储是惰性过期的，过期的东西不会自己消失，得你去删。所以认领之前先整理一遍：清掉已经
过期的，剩下的要是已经到 maxNonces 了就按最旧的开始淘汰，保证不能被构造出来的大量随机
nonce 把内存撑爆。淘汰掉的那些再来就当成新的，这个我认；但刚用过的那条必须还在，重放照样
得拦住。

时间窗和错误码也别糊弄。时间戳只认纯数字，差超过 windowMs 才算过期，正好卡在边上要放行——
有家合作方的机器时钟慢了几十毫秒，卡边就拒的话天天来找我。头缺了、keyId 不认识、密钥已经
停用、body 摘要对不上、签名对不上，这几种要分开报 code，别都塞一个 400 回去，我排障就看
这个。比签名用 timingSafeEqual，长度不一样或者根本不是 hex 的直接判不过，别把 crypto 抛的
错漏到外层变成 500。计数器 README 里列了那几个名字，通过、被拒、每种拒绝各一笔都得计上，
rejected 要等于各分类加起来，我对账用。
