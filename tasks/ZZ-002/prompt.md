我们做包装和贴纸的拼版，天天要处理轮廓：给外轮廓并一圈出血、把两个图案重叠的部分切出来、
把 logo 从底图上挖掉。以前都丢给在线工具，现在客户现场不让传文件，得弄个离线的网页版。

轮廓数据我导了几组在 samples/shapes 里，是闭合的折线点序列，有的一组轮廓带孔，
格式和字段见 README，别改。samples/expected.json 是我手算的期望结果：面积、轮廓条数，
还有一批点该在结果里还是外面——这就是验收标准，跑完逐条对给我看。

并集、交集、差集、异或四种都要有，填充规则 even-odd 和 nonzero 两种都得支持，
同一个图形两种规则出来的结果不一样，别混着来。轮廓可能自交，可能一条整个套在另一条里面，
可能共边共点，也可能正好在顶点上相切，这些都得给出确定结果，不许崩、不许画出开着的缺口。

几件我特别在意的。第一，结果得可复现：同一个输入跑两遍，导出的 JSON 要一模一样，
不能因为遍历顺序变了轮廓顺序、或者每条轮廓的起点就飘了，两次一比对不上，这数据就没法用。
轮廓之间怎么排、每条轮廓从哪个点起，你自己定一套规则，写进 README，然后照着来。

第二，结果要能拿去当输入再用一次：把导出的结果喂回去、跟空集做同样的运算，图形不能再变，
面积不能每次差那么一点点。这条现在不加，等哪天发现面积一直在抖就晚了。

第三，画布上点一下，要能告诉我这个点在不在结果里，按当前选的填充规则算。
缩放平移要有，包围盒和面积实时显示，我好对着 expected.json 核。

第四，最狠的一组是五千个顶点的轮廓跟一个大矩形做运算，别跑成好几分钟，
算的时候界面不能白屏，算完把耗时打出来。容差用 README 里写死那个值，别自己调。

README 里写清楚算法思路、容差怎么定、两种填充规则怎么处理、导出格式、确定性怎么保证，
还有自检怎么跑——点一下、或者一条命令，把 samples 里几组全跑一遍对答案。
