财务那边现在是用表格对账的，上个月有人把一笔分录直接改了个数字，月底怎么都对不上，
查了三天才查出来是被人动过。想在这仓库里把复式记账这块写出来：只认分录，记错了只能冲正，
封账以后的期间谁也不许动，金额一律整数分，别给我上浮点。

入口一个 createLedger，README 的《口径》和《API》两节把账户怎么定义、分录要满足什么、
什么顺序报错、冲正怎么算、封账怎么生效、余额和试算表的口径、每种错误报哪个码都写死了，
照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，
就差 lib/ledger.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。币种得分开算：账上是能混着好几个币种的，一笔分录里每种币种各自
求和都必须是零，拿不同币种的金额互相抵是不认的，报错要说清是哪个币种差了多少。金额只认
不为零的安全整数，零、小数、超过安全整数范围的都得拦下来。

报错的先后顺序我是真在意，因为线上就是靠这个定位问题的：先看入参和 id、日期合不合法，
再看这个日子是不是已经封账了，然后才看 id 重不重复，接着逐笔看账户和金额，最后才算平不平。
也就是说封账期间里递一条重复 id 上来，我要看到的是期间的问题，不是重复的问题。

冲正这块：原分录一个字都不许改，冲正分录单独一条、id 是原 id 后面加 :rev，金额全取反；
冲过的不能再冲，拿冲正分录本身去冲也得拦住。余额按日期累计，asOf 当天要算进去；
试算表按账户类型汇总，除了借方为正的净额，还要给一个按业务习惯摆正方向的数，
两边加起来是零才算平。

跑法两条：npm test 全绿（12 条，里面有分币种平衡、账户与金额与分录的校验、检查顺序、
日期合法性、冲正与重复冲正、封账与往回推、余额的日期边界、试算表的分类与方向、
分录筛选与统计口径），npm run demo 的输出跟 README 最后贴的那段一行行对上。
