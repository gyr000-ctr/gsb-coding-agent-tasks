榜单那块要重写一遍：一份有序集合，成员带分数，按分数从低到高排，同分的按成员名排。除了增删改查，
还要能查名次、按下标切片、按分数区间和按字典序区间捞人 —— 后台页面上一堆地方在等这几个接口。

入口就 createZset，出来的对象上有 add / remove / score / size / rank / revRank / range /
rangeByScore / countByScore / rangeByLex / entries / clear，README 的《口径》和《API》两节是
标准答案：一条记录长什么样、什么算非法参数、排序怎么定、名次从几开始、负下标怎么算、越界怎么截、
分数区间开不开、字典序那四种边界写法各是什么意思、哪些查询返回新数组、每种参数错报哪个码，
都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，
就差 lib/skipzset.js，别的文件不动（用例是标准，别改用例去迁就实现），也别引第三方包。

容易写歪的地方：名次是 0 基的（第一个是 0，不是 1），revRank 数的是从分数最高那头往下的名次，
找不到人一律 null 别抛错；排序是「先分数、后成员」，同分的时候按成员名的字符串序排，别按插入
顺序；range 的负下标是各自先加 size 换算成正的，再把两端截到 [0, size-1]，换算完 start > stop
或者集合是空的那就返回空数组，别返回 null 也别抛错；rangeByLex 跟分数一点关系都没有，只看成员名，
而且返回的成员要按成员升序 —— 别顺手沿用集合自己的（分数）顺序；add 对已经存在的成员是返回 0，
哪怕这次把分数改了也是 0；分数只收有限数字，NaN 和正负无穷都不行，但分数区间的边界是允许正负
无穷的；字典序边界就四种写法，'-'、'+'、'[值'、'(值'，别的（比如光写个 'b'，或者空字符串）
都是 ERR_BAD_BOUND，别自己往「开区间」上猜；所有查询吐出来的数组都是新的，改它不许动到集合内部。
