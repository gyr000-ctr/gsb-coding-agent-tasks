我们网关的转发层一直是个雷，这次想自己重写一遍，这块交给你。

仓库 ./relayguard 是 Node 写的，配置、计数器、HTTP 入口和一组用例都在，唯独 src/forwarder.js
里那层转发是空的，现在只会抛 not implemented。README 把配置字段、预算头叫什么、重试规则、
计数器的名字都写清楚了，照着来；configs 里的配置、计数器的名字、test 里的用例别改。

最要紧的是超时。上游不止一个，慢的也不少，链路上一跳会给我们传一个剩余预算
（请求头 x-request-budget-ms，README 里有），本地转发花掉的时间要从里面扣掉再传下去。
预算见底就立刻 504，别让上游还在那儿跑着——发出去的那个请求要取消掉。整个请求从进来到
返回，不能超过最开始读到的那个预算。

重试要有选择。只有幂等方法（GET/HEAD/PUT/DELETE）才重试，而且只重试连接层面的失败
（连不上、连接被重置、响应头都没回来就断了）和上游明确的 502/503/504；方法本身不是幂等的，
一次机会都不给。响应头只要回给客户端了，body 断半截也不能再重试，这点上周刚被坑过。
每次重试之前先看剩余预算够不够，不够就放弃，按已经拿到的东西返回。

请求体有个坑：第一次转发的时候 body 已经读掉了，重试要能原样重放，但只缓存小于
replayLimitBytes 的那些；超过阈值的不缓存，遇到需要重试就直接报错，别把半截请求发出去。
超过 maxBodyBytes 的直接 413，别转发。

客户端断开的时候，往上游的请求要跟着取消，这种中断不算上游错误，也不要触发重试，
不然上游错误率会被这些中断刷得很难看。计数器 README 里列了那几个名字，每次尝试、每次重试、
预算耗尽、上游错误都要计上。

别装任何包，node 20 的标准库够用，package.json 保持现在这样。npm test 里那组用例现在是红的，
做完要全绿。
