缓存层要扩容，现在 key 是取模分的，一加机器就得全量刷一遍，半夜加节点能把后端打穿。想在这
仓库里写个一致性哈希的分片环，把选分片这块换掉。

入口一个 createRing，README 的《口径》和《API》两节把虚拟节点怎么铺、点怎么排、key 怎么查、
副本怎么走、迁移计划里那几个字段怎么算、每种错误报哪个码都写死了，照着来。目录里
lib/hash.js、lib/errors.js、test 下三组用例、scripts/demo.mjs 都已经写好，就差 lib/ring.js
里的 createRing，别的文件别动，也别引第三方包。

几件我特别在意的事。虚拟节点的名字和点数是定死的，哈希也只能用 lib/hash.js 那个，不然两个
进程算出来的分片就不一样了——线上最怕这个。点撞在一起的时候排序也得有个准头，别这次这样
下次那样。

加一个节点只该动它自己那一段，别的 key 一个都不许挪；去掉一个节点，原来归它的那些落到剩下的
环上，其余的不动。这条要是做错了，扩容就等于全量失效。权重也得真起作用，大机器多分点。

迁移计划是给运维看的：谁从哪挪到哪，按 key 排好，两边各分片各分到多少，加总得对得上。
keys 里有重复的别给我算两遍。

跑法两条：npm test 全绿（21 条，里面有专门盯绕回、加节点迁移范围和权重比例的），
npm run demo 的输出跟 README 最后贴的那段一行行对上。
