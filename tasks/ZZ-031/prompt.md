我们想在后台做个小表格功能，用户填的是 Excel 那种公式（=A1+B2*SUM(C1:C9) 这种），
想在这仓库里把引擎补出来。

入口一个 createEngine，README 的《口径》和《API》两节把值有哪几种、公式语法和优先级、
各个函数的口径、类型怎么强制转换、错误值怎么传、引用和范围怎么写、依赖怎么算、
set 返回什么、每种错误报哪个码都写死了，照着来。目录里 lib/cells.js、lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/engine.js，别的文件别动，
也别引第三方包。

公式解不开不能抛异常，那格得变成 #ERROR!，其余格子照常算，否则用户
一边打字整个表就崩了。IF 必须只算走到的那个分支，IF(FALSE,1/0,5) 得是 5，不能先算完再挑。
错误值要一路往外传，SUM、算术、比较都一样，但 IF 没走到的分支不算数。

重算只做增量的：改一格，只有它和直接间接依赖它的格子参与，范围依赖要按展开后的每一格算，
范围外的一格都不能碰，stats 里要能看出这一轮算了几格。依赖表得按最新公式重建，把公式改成
常量、常量改回公式，下游都得跟着走。

循环引用不能死循环也不能崩：环上的格子和依赖环的格子都是 #CYCLE!，把环里某一格改成常量
或者改到不再依赖环上，链上要立刻恢复成正常值。范围把自己也圈进去（比如 H1 = SUM(G1:H1)）
也算绕回自己。

跑法两条：npm test 全绿（14 条，里面有优先级与一元负号、类型分档比较、IF 惰性、
错误值传播、跨表引用、增量只算受影响的部分、范围依赖、改出环和打破环），npm run demo
的输出跟 README 最后贴的那段一行行对上。
