手头有个只带 deflate 数据的下载包要在这边解，环境里没有第三方解压库，想自己写一份 inflate：stored、
固定霍夫曼、动态霍夫曼三种块都得认，外面还要能直接吃 zlib 包（头 + deflate 数据 + 尾部 Adler-32）。

入口就 inflateRaw / inflateZlib / adler32，README 的《口径》和《API》两节是标准答案：位怎么读、
三种块各长什么样、动态表的码长怎么重复、码表什么时候算不合法、长度和距离的基数表跟附加位、
距离越界和重叠复制怎么算、zlib 头哪几个字段要查、尾部校验怎么对、哪些入参抛哪个码，都写死了，
照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/flate.js，
别的文件不动（用例是标准，别改用例去迁就实现），也别引第三方包 —— 用例和 demo 里会拿 node:zlib
造数据，lib/flate.js 里不许碰它。

容易写歪的地方：位序是两套 —— BFINAL / BTYPE / HLIT / 附加位这些字段低位在前，霍夫曼码字反过来
是高位在前，解的时候得跟着码字位数从最高位一位一位往树里走；stored 块要先把当前字节里剩下的位
丢掉（跳到字节边界）再读 LEN 和 NLEN 两个 16 位小端，LEN 的反码必须等于 NLEN，这里对不上或者
数据不够就是不同的码；动态表那个码长表，19 个 3 位码长是按 16,17,18,0,8,7,9,... 这个固定顺序摆的，
不是从 0 号开始摆，后面用 16 复制的是"前一个码长"，第一项就撞上 16 直接报错；码表不完整（有分支
空着）只有"整张表恰好一个码"才允许，距离表允许整张都是 0，字面长度表里没有 256 也是错；解到 256
才算这个块结束，最后一个块结束之后 raw 流后面再有字节都不看，但 zlib 那边数据后面必须正好剩 4 个
字节的 Adler-32，多一个少一个都是错，别顺手把多余的当填充；距离小于长度是合法的重叠复制（一个
'a' 后面跟「长度 3、距离 1」要解成 aaaa），得一个字节一个字节往回抄，先把源片段切出来再拼就错了。
