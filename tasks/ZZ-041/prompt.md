备份现在是无脑整份存，同一份数据存十个版本就占十份空间，删了也不知道什么时候能真的把底层那些块释放掉。想在这仓库里写个按内容切块、块级去重的存储。

入口一个 createDedupStore，README 的《口径》和《API》两节把怎么用滑窗滚动哈希定切点、常数取多少、块长上下限怎么生效、块的 sha256 怎么算、引用计数怎么记、删除和 gc 分别做什么、快照怎么钉住对象、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/dedupstore.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。切块那一套要一字不差地照做：每一块都从 h 等于零重新攒，所有运算都是 32 位无符号回绕，切点只看这一块自己的字节。这套东西的价值就在"前面插几个字节，后面那一大段还能复用"，所以中间只要有一处写错，插入一个字节就整份重切，去重全废。

引用计数要按"块被引用了多少次"记——同一个对象里同一块出现两次就加两次；deleteObject 只减引用不删块，真删是 gc 干的。被快照钉住的对象不许删，报错里要说清是哪些快照钉的；快照里同一份对象写两遍只算一次。存进去的和拿出来的都必须是拷贝，外面改它不能影响库里那份。

跑法两条：npm test 全绿（14 条，里面有几组固定数据的切点与块长、空数据与短数据、同内容第二次全复用、前缀插入只动开头、重复片段复用、存取都是拷贝、别人还在引用的块不被回收、gc 回收与统计对齐、快照钉住与解钉、restore 列表、integrity 自检、参数与错误码），npm run demo 的输出跟 README 最后贴的那段一行行对上。
