前缀表这块想自己写一份：IPv4 和 IPv6 的地址解析、最长前缀匹配、还有按值把相邻前缀合成的聚合，
都要在同一张表里跑起来，谁插进去、谁盖了谁、删掉之后回落到哪一条，都得是确定的。

入口就 parseAddress / parsePrefix / formatAddress / createTable，README 的《口径》和《API》
两节把地址怎么写、前缀的主机位有什么要求、value 用 BigInt 怎么摆（v4 32 位、v6 128 位）、
IPv6 的文本按 RFC 5952 怎么压缩（最长的一段全零、一样长取靠左的那段、全零写 ::）、
entries 按什么排、remove 之后空壳节点怎么剪、lookup 没命中返回什么、aggregate 合兄弟的三种条件
（两个都是叶子、值相等、父前缀本来有值就得值也相等）和"少掉的条目数"怎么数、每种输入报哪个码
都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，
就差 lib/cidrroute.js，别的文件不动，也别引第三方包（BigInt 是标准库里的）。

容易写歪的地方：parsePrefix 里不管哪儿有毛病都报 ERR_BAD_PREFIX，别把地址那套 ERR_BAD_ADDRESS
漏到前缀接口上来；主机位不是 0 的（10.1.2.3/8 这种）要直接拒；规范化时 IPv6 该补 ::、该取靠左
那段、该小写、不补前导零，2001:0DB8:0000::/32 出来得是 2001:db8::/32；IPv4 段不写前导零，
010.1.2.3 不算合法。lookup 要一路走到最深的那个有条目的节点，别在半路停；remove 只删条目，
空壳剪掉但别把兄弟的路径弄断；aggregate 是一路往上合的，合完还要再试父节点，父前缀已经有别的
值时必须拦住。值跟值相等是按规范化文本比的，{a:1,b:2} 和 {b:2,a:1} 算相等，数组顺序不一样就不算。

跑法两条：npm test 全绿（13 条，里面有地址解析、前缀规范化、两个家族的非法输入、
insert/exact/has/size、最长前缀匹配、entries 的排序、remove 后的回落与剪枝、aggregate 的合并
与三种合不动的情形、值按结构比较、以及各条错误码），npm run demo 的输出跟 README 最后贴的那段
一行行对上。
