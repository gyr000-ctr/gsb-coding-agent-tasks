关键词命中这块想自己写一份：一堆词丢进去，然后在长文本上把它们出现过的每一个位置都找出来，
重叠的、同一个位置长短都命中的、一块一块喂进来还被切开的字符，都得报对。

入口就 createMatcher、createScanner、scan，README 的《口径》和《API》两节把模式表怎么校验、
位置按码点怎么数、排序怎么排、maxMatches 到了怎么办、流式那边跨块的匹配什么时候报、
半个代理对怎么压着、pending 是什么、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/matchgrid.js，别的文件别动，
也别引第三方包。

位置和排序这块最容易写歪：位置是码点不是 UTF-16 的 code unit，'a😀b' 里 b 的位置是 2；
同一处按长度降序先报长的，再按模式表里的先后，重叠的起点一个都不能漏。ignoreCase 是逐码点
折 lowercase，折完码点数会变的那种字符（比如 İ）当它没折，不然位置就全错位了；折完重样的
模式也算重样，得报错。

流式那边：push 只报「在这一次 push 里结束」的匹配，跨块的攒着，index 是从这一路开头算的
全局码点位置；一块的末尾如果是半个代理对就先压着不喂，下一块补齐了再算。pending 是还悬着的
尾巴——从当前自动机状态顺着失败链往上找第一个还有出边的状态（根不算），它的深度就是，
找不到就是 0。maxMatches 是整条流一起算的，不是每块单独算。

跑法两条：npm test 全绿（12 条，里面有重叠与同处长短排序、码点定位、ignoreCase 与折完重样、
maxMatches 截断、模式表拷贝、错误码、跨块才报、代理对被切开、跨块位置连续、pending 与封口、
流里的上限），npm run demo 的输出跟 README 最后贴的那段一行行对上。
