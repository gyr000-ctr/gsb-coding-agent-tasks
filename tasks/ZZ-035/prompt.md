报表现在是一条条 SQL 打到数据库上，测试环境没库、口径还老变，想在这仓库里写个在内存里跑的查询引擎把这块接过来。

入口一个 createEngine，README 的《口径》和《API》两节把表怎么建、列怎么引用、输出行的键怎么取、条件怎么写、null 和类型不同时算什么、左连接补 null 怎么补、分组和聚合忽略什么、空表怎么算、distinct 去重、排序稳定性与 null 排哪、having 和 orderBy 能引用什么、分页顺序、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/engine.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。条件判定是三值的：类型不一样或者沾上 null 都是"不知道"，只有 true 才通过，所以字符串 '1' 匹配不上数字 1，null 也不等于任何东西，这条弄错报表数就全飘了。左连接挂不上的行右表列要补 null，而且那些 null 后面还要能正常参与分组（自己占一组）和聚合的忽略规则。

聚合的空集口径要分清：不分组的时候哪怕一行都没有也得给一行，count 是 0、其余是 null；分了组但一组都没有就是零行。输出里的键名规则也别搞混，有 join 的时候键是 带表名的。

跑法两条：npm test 全绿（15 条，里面有三值判定与类型规则、in/is-null、投影与稳定排序、distinct 与分页顺序、左右连接的补 null、分组聚合与空集、having 与聚合别名、各条参数与错误码），npm run demo 的输出跟 README 最后贴的那段一行行对上。
