服务现在有三种来源的配置：默认值、环境、用户手改，优先级一层比一层高，想合成一份最终配置，还得知道每个值到底是谁给的。

入口一个 mergeConfig，README 的《口径》和《API》两节把输入形状、合并规则、数组和 null/undefined 怎么处理、环境变量怎么插值、来源怎么记、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/config.js，别的文件别动，也别引第三方包。

合并规则要稳：两边都是对象就递归往下合，兄弟键不能被吃掉；数组整体覆盖不拼接；null 是显式清空，undefined 是这层不管这个键（新键也不该被创建）；空对象不算清空。返回的 values 必须是深拷贝，改它不能污染传进来的层。

插值在合并之后做，只对字符串，一次就够：${VAR} 用环境变量，${VAR:-默认} 在缺失或空串时用默认，缺了又没默认就抛 ERR_MISSING_ENV；贴进去的值按字符串算，替换完的内容不要再扫一遍。sources 里对象用点号连路径，数组算一个叶子，某个键被后面整体覆盖时它下面的旧记录要清掉。

跑法两条：npm test 全绿（14 条，里面有深合并与兄弟键、数组覆盖、null 与 undefined 的差别、优先级顺序、深拷贝、插值默认值、缺变量报错、只替换一轮、来源追踪），npm run demo 的输出跟 README 最后贴的那段一行行对上。
