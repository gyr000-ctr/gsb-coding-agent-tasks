我们那个本地落盘的二进制格式要动一动了：上游的数据是别人用另一套工具写的，字段比我们多，
以前直接按自己认识的字段解完再写回去，不认识的字段就被抹掉了。另外还有人手写过 varint，写成了非最短的形式，我们这边也得照收不误，但自己写出去必须是最短的。
想在这仓库里把这块编解码写出来。

入口一个 createCodec，README 的《口径》和《API》两节把 schema 长什么样、key 怎么拼、
五种类型各自的写法、字段排序、未知字段怎么留、什么算坏字节、每种错误报哪个码都写死了，
照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，
就差 lib/wirecodec.js，别的文件别动，也别引第三方包。

写的时候字段一律按编号升序，跟 schema 声明的顺序、跟对象里键的顺序都没关系，
repeated 的多条按数组顺序挨着；值是 undefined 或者 null 就当没给，一个字节都别写出去；
变长整数永远最短形式。不认识的字段要原样带过去——解的时候连同 key 一起留在 unknownFields 里，
写的时候跟已知字段合并以后一起按编号排序，位置变了没关系，字节不能变。这几点合起来才是
"我读完再写回去，人家还认"。

读的时候别手软。字段号是 0、wireType 是 3/4/6/7、已知字段的 wireType 跟 schema 对不上，
这些都得当场报；变长整数超过五个字节或者第五个字节超出 32 位，也要报；字符串必须是合法 UTF-8，
别拿替换字符糊过去。反过来，非最短形式的 varint 是能收的，收完重编码要收回最短，这条别搞反。

跑法两条：npm test 全绿（17 条，里面有字段排序、zigzag 的正负边界、字符串与字节串与布尔、
repeated 与覆盖、未知字段保留、非最短 varint 的规范化、截断、超长、非法 wireType、
非法 UTF-8、必填缺失、schema 校验），npm run demo 的输出跟 README 最后贴的那段一行行对上。
