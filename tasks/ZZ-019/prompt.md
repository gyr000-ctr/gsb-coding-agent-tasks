口径（配置字段、判定顺序、被拒时怎么给等待时间、错误码）我都写在 README 的《口径》和
《API》两节里了，是定死的。目录里 lib/clock.js（时钟）、lib/errors.js、test 下三组用例、
scripts/demo.mjs 都写好了，就差 lib/gate.js 里的 createGate，别的文件别动，也不引第三方包。

桶要按真实时间线性补，不是每分钟整块加。我们有些客户是 2.5 个每秒这种小数速率，
补出来的令牌别被浮点尾巴带偏，判定要能对得上。

窗口要精确滑动。1 秒 5 次就是"最近一秒里 5 次"，不是每秒整段清零，正好隔了一秒的那条
要滚出去。被拒的时候给客户算的等待时间要能对得上：按桶缺多少令牌、或者按窗口里最早那条
什么时候过期，取最短的那个。

判定和扣额度必须分开。被拒的请求一个令牌都不能吃掉，尤其是几道上限同时看的时候。
批量判定也一样：一批请求里只要有一笔过不去，整批都不生效，别出现"前几笔扣了、最后一笔
失败"这种半截状态。同一批里同一个客户的两笔也要互相看得见。

时钟回拨不能白给额度。我们的 clock 是注入进来的，回拨的时候按上一次见过的时间算，
既不补令牌也不清窗口记录。

进程重启之后要能接上。快照里带上桶的令牌和窗口里的记录，restore 之后限流接着走，
别重启一次就把所有客户的窗口清空了。

跑法两条：npm test 全绿（18 条，里面有专门盯时钟回拨和批量原子性的），npm run demo 的
输出跟 README 最后贴的那段一行行对上。
