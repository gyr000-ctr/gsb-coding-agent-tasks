列表那边有个反复出现的毛病：整块重建。每次数据一变就把列表清空重排，DOM 抖、动画断、输入框里的光标也丢。
要个正经的键控 diff：给两份带 key 的列表，算出该删哪条、插哪条、哪条内容变了、哪条要挪到哪儿，
挪位置的时候尽量少挪 —— 已经排好相对顺序的那批别去动它，不然一段列表整体挪一位就全变成 move 了。
环境里没有现成的，自己写一份。

入口两个，diffLists 和 applyOps，README 的《口径》和《API》两节是标准答案：key 怎么取、操作流分几段、
每段的顺序是什么、index 相对谁算、update 什么时候才出、哪一批算「不用挪」、挪的时候插到哪儿、
move 的 from 和 to 各是什么意思、回放时哪些情况要报错，都写死了，照着来。目录里 lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/listdiff.js，别的文件不动（用例是标准，
别改用例去迁就实现），也别引第三方包 —— 更不是让你全删全插糊过去，用例会数你挪了几条。

容易写歪的地方：index 一律是「前面那些操作都做完之后」的位置，删完两个前面的，第三个的 index 就变小了，
别都按 prev 里的原始下标给；插入位置是「它在 next 里的前一条现在在哪儿」再加一，不是它在 next 里的下标；
update 的判据就是 JSON.stringify 比一下，一样就不出这条，别自己写一套深比较；不用挪的那批是目标位置序列的
最长递增子序列，用耐心排序（tails 里放的是下标，二分找第一个 >= 当前值的槽位替换）加前驱回溯挑出来，
别写成「从左往右看见乱的就挪」那种贪心，那样挪的条数会多；剩下的按目标位置从小到大挪，摘出来以后插在
「最后一个目标位置比它小的」后面，前面没有就插 0；挪的条数必须正好是列表长度减 LIS 长度，而且不许出现
from 和 to 一样的白挪。回放那边别偷懒按 key 重新找位置就算了 —— remove 和 move 的 index / from 必须跟
那条 key 现在的位置对上，对不上要报 ERR_BAD_OPERATION，这样操作流本身也能被验；applyOps 得返回新数组，
原数组和里面的 item 都不许改。key 取不到（null、空串、对象、NaN、Infinity）和同一侧 key 重复分别是
ERR_BAD_ARGUMENT 和 ERR_DUPLICATE_KEY，details 里要带上 index / side / key，别糊成一种。
