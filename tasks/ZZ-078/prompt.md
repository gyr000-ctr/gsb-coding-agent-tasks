DNS 那边想自己拆报文，不引三方库：问询、资源记录、名字压缩指针、几种常见 rdata 的拆装，还有按
maxSize 做 TC 截断；环境里没有现成的，自己写一份。

入口两个，encodeMessage 和 decodeMessage，README 的《口径》和《API》两节是标准答案：12 字节头怎么摆、
标志位那 16 位谁在哪、名字和压缩指针怎么编怎么解（包括偏移上限 0x4000）、A / NS / CNAME / SOA / PTR /
MX / TXT 各自的 rdata 长什么样、不认识的类型怎么原样带回去、按 maxSize 截断时按什么次序丢记录、
tc 什么时候置位、四个错误码分别在什么时候抛、details 各带什么，都写死了，照着来。目录里 lib/errors.js、
test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/dnscodec.js，别的文件不动（用例是标准，别改用例
去迁就实现），也别引第三方包 —— 更不是让你拿几组固定向量糊过去，用例里既有写死的字节向量，也有编了再
解来回对。

容易写歪的地方：标签最长 63 字节、整个名字的线上长度（含末尾 0）不超过 255 字节；根名字是空串、编出来
只有一个 0 字节，而 'a..b' 那种空标签要当错；名字按 Latin-1 走，码位超过 0xff 的字符（比如中文）
既编不了也解不了。压缩表只收起始位置小于 0x4000 的后缀，所以指针永远指不到 0x4000 及以上；比对后缀时
按小写算，但解码展开时大小写照写进去的来。解指针要防绕圈，还要能指到前面任何位置 —— 比如某条记录
rdata 里的名字。rdata 长度得跟内容严丝合缝：A 不是 4 字节、名字型 rdata 没用完、MX 短于 3 字节、
TXT 段伸出 rdata、SOA 后面 5 个整数没凑齐，都算坏记录，别睁只眼闭只眼往下走。标志位里 tc 是 0x0200、
rd 是 0x0100、ra 是 0x0080、opcode 在 0x7800，别摆错；id 得是 0..65535 的整数。maxSize 不给就是不截，
给了必须是不小于 12 的整数，超了就从 additional 开始往前丢（additional -> authority -> answer ->
question），丢到装得下为止，动过刀子的报文 tc 置 1；每丢一轮都要拿新的条数把整条报文重算一遍
（压缩偏移也跟着变），不能拿旧的字节直接砍尾巴。

跑法两条：npm test 全绿（10 条，里面有最小问询的字节、标志位、压缩偏移和 0x4000 上限、maxSize 的
丢记录次序、编了再解、各种入参报错），npm run demo 的输出跟 README 最后贴的那段一行行对上。
