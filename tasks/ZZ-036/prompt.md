我们现在跨库写是靠"先写这边再写那边"，中间挂一个库就两边对不上。想在这仓库里写个两阶段提交的协调器：先问一圈能不能提交，全票通过才提交，有人不同意就回滚，决定之后要保证每个人都收到，协调器自己崩了重启也不能改主意。

入口一个 createCoordinator，README 的《口径》和《API》两节把消息怎么攒怎么取、事务的 id 和 ops 怎么校验、投票到什么程度算定案、投 no 和超时分别怎么算、决定之后怎么重发重发给谁、ack 什么时候认、幂等怎么算、崩溃丢掉什么留下什么、恢复时每种日志怎么处理、计数哪些是持久的哪些是内存的、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/coordinator.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。全票才算通过，差一个人就是没定案，别提前拍板。决定一旦写进日志就再也不能变，恢复的时候也是一样：没决策的一律回滚，决策过的只补发没回执的人，绝不能因为"没收到回执"就改成回滚。

重发要按退避来，而且只发给没回执的，别每次 tick 都全量轰一遍。重复的投票和重复的 ack 只是重复，不能把票改了也不能把状态推回去。崩溃是把内存里的东西清空（包括计数）、日志留着，恢复之后那几个计数得按日志重建出来。

跑法两条：npm test 全绿（12 条，里面有全票提交与收齐回执、投 no 立刻回滚、超时回滚、退避重发给未回执的人、重复投票与 ack、崩溃后未决策回滚、已决策不改卦只补发、已完成不重发、恢复后 id 仍算用过、各条参数与错误码），npm run demo 的输出跟 README 最后贴的那段一行行对上。
