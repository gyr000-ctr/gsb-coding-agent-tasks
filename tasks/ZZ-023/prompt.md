我们那张实时看板现在是拿每分钟跑一次的定时任务凑的，事件时间一乱就全乱套：网络恢复以后
补上来的那批历史事件被当成"现在"的，窗口一关就再也补不进去，运营看到的数一会儿多一会儿少。
想在这仓库里写个正经的窗口聚合，把这块接过来。

入口一个函数，README 的《口径》和《API》两节把窗口怎么切、水位怎么走、关窗怎么判、一次 push
输出几条、记录长什么样、统计怎么数、什么情况报哪个码都写死了，照着来。目录里 lib/agg.js、
lib/errors.js、test 下三组用例、scripts/demo.mjs 都已经写好，就差 lib/stream.js 里的
createAggregator，别的文件别动，也别引第三方包。

几件我特别在意的事。水位只能往前，不许因为来个时间更小的事件就往回退，不然前面关掉的窗口
会被重新打开，那是灾难。判定顺序也要对：先把水位推上去、把到期的窗口关掉，再看这次的事件
自己落在哪儿——所以一次 push 完全可能先吐两条 final 再吐它自己的 preliminary，顺序别乱。

迟到要看宽限期：还没关的窗口，迟到的事件照样得算进去，final 的数值必须等于最后一次
preliminary 的。关掉了的窗口就别再碰，那些直接丢掉、计数记上，别回头又给它算进去。

窗口也不能一直留着。关掉的窗口过了保留期就得整个放掉，内存要能降下去；已经放掉的窗口再查
应该是没有，不是查出来一个空的在那杵着。

跑法两条：npm test 全绿（20 条，里面有专门盯关窗顺序、宽限期边界、水位不倒退的），
npm run demo 的输出跟 README 最后贴的那段一行行对上。
