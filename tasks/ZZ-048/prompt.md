导出任务老是把自己跑挂：数据量一上来就全读进内存，几百万条直接把进程顶爆。想在这仓库里
写个有界内存的外部归并排序，攒够一批就排好扔到磁盘上，最后再合回来。

入口一个 createSorter，README 的《口径》和《API》两节把参数默认值、攒到多少落盘、
溢出文件叫什么名字、文件内容长什么样、收尾怎么归并、什么时候删文件、统计口径、
每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs
都已经写好，就差 lib/extmerge.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。稳定性不能丢：compare 说两条一样的时候，得按推进来的先后次序排，
所以每条记录要带着到达序号一路走到底，落盘之前那一批也要先排好再写，别把乱序的原始批
扔到文件里等着最后再排。溢出文件名是 run-0001.jsonl 这种四位连续编号，一行一条 JSON，
每行都以换行结尾，归并阶段产生的中间文件接着这个号继续往下排。

收尾这块最容易漏：内存里剩下的一批也要管——盘上已经有文件就把它也落成一个 run，
一条都没落过就直接在内存里排完；然后按 fanIn 分批归并，一轮一轮把路数压下来，
run 数已经不超过 fanIn 时直接合在内存里出结果。收尾之后这次写出去的临时文件必须
一个不剩地删掉，之后再 push 或者再 finish 都得报错，别悄悄又给我跑一遍。

跑法两条：npm test 全绿（11 条，里面有装得下不落盘、空输入、稳定性、三百条小内存的正确性、
超过 fanIn 的归并轮数、自定义比较函数、溢出文件的名字与行数与内容、收尾清理、统计口径、
各种配置错误、收尾之后的状态错误、塞不进 JSON 的条目），npm run demo 的输出跟 README
最后贴的那段一行行对上。
