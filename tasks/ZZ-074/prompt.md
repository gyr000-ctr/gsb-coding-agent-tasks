前端那边要个小东西：我们自己的那棵节点树（就是普通对象，tag / attrs / children 那种）上得能直接跑 CSS 选择器，
用来做高亮和定位。不想为这个把 jsdom 之类拖进来，环境里也没有现成的，自己写一份。

入口就两个，parse 和 queryAll。README 的《口径》和《API》两节是标准答案：节点什么形状、支持到哪些选择器、
AST 里每个字段叫什么、优先级怎么数、组合子怎么走、属性那六种比较各是什么语义、伪类的第几个孩子怎么数、
:not 算谁的、报错时 details 里的 position 指哪个字符，都写死了，照着来。目录里 lib/errors.js、test 下两组用例、
scripts/demo.mjs 都已经写好，就差 lib/selmatch.js，别的文件不动（用例是标准，别改用例去迁就实现），
也别引第三方包 —— 更不是让你把常见写法挑几个糊过去，属性比较、nth 公式、相邻兄弟、报错位置这几样都会算错。

容易写歪的地方：空白就是后代组合子，可显式组合子前后的空白不算，parts 里第一段的 combinator 固定是 null、
从第二段起才有值；标签名和属性名统一小写存，类名、id、属性值保持原样，但查属性得按不区分大小写找键；
`*` 和标签名只能待在一个复合选择器的最前面，`*div` 是要报错的；AST 里属性是 {name, op, value}，
只写 [a] 的时候 op 和 value 都是 null，伪类是 {name, arg}，first-child / last-child 的 arg 是 null；
优先级三段里 :not 自己不算，算它括号里那个复合选择器的；nth 数的是元素兄弟、从 1 开始，夹在中间的文本节点
既不算兄弟也不参与计数，nth-of-type 只数同标签的；`+` 只找紧挨着的上一个元素兄弟（中间隔个文本节点照样算相邻），
`~` 是往前找任意一个；root 自己就算匹配上也不进结果，可它算祖先，所以在 root 上查 `ul > li` 能查到它的儿子；
结果按前序排、命中多个组也只出现一次；属性那边 ^= / $= / *= 的值是空串时永远不匹配，~= 按词比，
[a|=v] 是等于 v 或者以 v- 开头。报错位置这条最容易想当然：nth-child / nth-of-type / not 括号里不管出什么毛病，
位置都报回那个 `(`；缺东西（组合子后面空了、逗号后面空了、少个 `(`）报到缺的那个位置，已经到末尾就是字符串长度；
两个 token 直接黏在一起接不上的，报到接不上那个字符。还有不带引号的属性值必须是标识符，所以 [data-x=1]
是不合法的，得写成 [data-x="1"]。另外 queryAll 别每个节点都重新 parse 一遍选择器，解析一次拿去套整棵树。

跑法两条：npm test 全绿（11 条，里面有解析形状与优先级、组合子的等价写法、属性六种比较、nth 各种公式与 :not、
前序与去重、:not 的补集性质、坏 root 与坏选择器、报错位置对照表），npm run demo 的输出跟 README 最后
贴的那段一行行对上。
