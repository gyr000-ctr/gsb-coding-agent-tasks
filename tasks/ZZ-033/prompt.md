我们的定时任务现在是各自一个 crontab，任务之间有先后关系的全靠"跑完手动触发下一个"，上游挂了也没人管，下游照样跑出半截数据。想在这仓库里把这些编排起来。

入口一个 createScheduler，README 的《口径》和《API》两节把 cron 怎么解析怎么按 UTC 展开、日和周同时限定时怎么算、任务定义的约束、level 怎么来、一次窗口里展开出哪些触发、依赖指的是哪一次上游、跑一轮时 perform 的三个返回值怎么算、重试怎么退避、上游挂了怎么往下传、统计口径、每种错误报哪个码都写死了，照着来。目录里 lib/errors.js、test 下两组用例、scripts/demo.mjs 都已经写好，就差 lib/scheduler.js，别的文件别动，也别引第三方包。

几个我特别在意的地方。cron 里日和周都写了的时候是并集不是交集，这个错了排出来的计划完全是另一回事；周那格 7 和 0 是同一个周日。展开只认整分钟，from 落在半分钟上，这一分钟不算，得从下一个整分开始。

依赖是"同一次计划里、这次触发之前最近的那一次上游"，找不到就不能硬算，要标出来并且跑的时候直接跳过。同一个时刻上游必须先跑，不然下游拿不到上游的结果。重试要有额度，退避是指数的；perform 说 fail 就是明确失败，别再重试；上游是失败还是跳过，下游的 reason 得分得清。你写的时候先规划模块结构，再下手。

跑法两条：npm test 全绿（13 条，里面有 cron 各段语法与并集/周日、依赖链与排序、找不到上游、退避重试到上限、fail 不重试、级联跳过、统计），npm run demo 的输出跟 README 最后贴的那段一行行对上。
