我们自己的登录令牌这块太散了，几个服务各写一套，这次想收成一个独立模块，仓库 ./tokenkeeper
就是给它留的位置。

骨架已经在里面了：HTTP 入口、配置、计数器、密钥集合的解析都有，用例也在，唯独 src/tokens.js
里那个服务是空的，现在只会抛 not implemented。README 把令牌长什么样、claims 有哪些、每一步
报哪个 code、计数器叫什么、密钥怎么滚动、撤销怎么算都写清楚了，照着来；已有文件的接口、
configs 里的配置、计数器名字、test 里的用例都别改。别装包，node 20 的标准库够用。

最要紧的是密钥滚动这块。新密钥上来开始签，老的那把留一段过渡期只验不签，过渡期一过就不认了，
这时候要单独报 key_expired；真把老的那把从集合里拿掉就报 unknown_kid，这两个别混成一句话。

refresh 是一次性的：换一次就作废，新的顶上，老的再进来哪怕只差一秒也算重放。真撞上重放
（客户端存了两份，或者被人抄走了）就把整条会话一起废掉，已经发出去的 access 也立刻不认，
别只把手里这张标记一下就算完——宁可让客户端重新登录，也不能让抄走的那份跟我们各跑各的。

撤销要能撤单条也能撤整条会话，撤完立刻生效。撤销表别做成只涨不落，过期的条子随时清，
但得有个硬上限：顶到上限的时候宁可拒绝新的撤销请求，也不能把还没过期的旧条子挤掉，
这个取舍我们认。时间上有容差，客户端比我们快几秒不能算过期，容差只用来挡这点钟差，
别顺手把有效期也一起放宽。

时间和随机都从外面注入（now、random，形状 README 里写了），实现里别直接写 Date.now、
new Date、Math.random，测试会塞假时钟进来看这几步。

计数器 README 里列的那几个名字别改，签发、换新、验过没验过、撤销、重放、容量顶了都要计上，
线上出问题我就靠它看卡在哪一步。
